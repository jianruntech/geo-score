Get started in five minutes

This quickstart installs Tidemark, runs it against the example site in the repository and walks through the report it prints. By the end you will know how to read a finding and how to make the build fail on the ones that matter to you.

What you need

  • A terminal.
  • A built static site, or the bundled example.
  • Five minutes.

How to run the first check

Point Tidemark at the folder that holds the built site and run the check command. The report groups findings by page, with the worst problems first.

This block is part of a test fixture. It exists so that the page carries enough server-rendered prose for the rendering check to treat it as a real content page rather than a stub. It describes nothing and promises nothing, and it names no person and carries no figure or timestamp, so that it cannot change how the freshness, byline or statistics checks read the page. Readers of the fixture can skip it; the scorer counts its words and nothing more, which is exactly what this block is for, and why it sits in a plain division rather than a paragraph, a list or a heading.
