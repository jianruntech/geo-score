# AIV 量表 v1.1

> 取代 [v1.0](v1.0.md)。v1.0 的报告不会因此失效，但两版分数**不可直接比较**——变更清单与标定依据见 [calibration-v1.1.md](calibration-v1.1.md)。

## 两个分数，不要混在一起

**站点就绪度** · 满分 100 — 站外可观测、且站方可修的部分。这是本量表打分的对象，也是服务能承诺的范围。

**AI 引用表现** — 用行业真实问题在主流 AI 搜索实测被引用情况。结果型指标，单独报告，不并入就绪度——它由就绪度与时间共同决定，且同一问题多次提问结果不同，不可复现。把它并进主分会同时伤害客户与口径可信度。

把二者并进一个 100 分，是这类量表最常见的错误。v1.0 正是这样把一个爬虫可达性满分、正文服务端渲染 60KB 的站判成「危急」——这个判决同时伤害客户与量表自己的可信度。

## 打分规则

1. **抽样**：恰好 8 个 URL——首页、2 个主要产品或服务页、2 个文档或知识页、3 个最近内容页。不足 8 页则全取，并在报告注明。
2. **阶梯给分**：取证据**实际**满足的最高档，不是差一点就到的那一档。这是区分度的来源。
3. **三种状态**：`已评分` / `不可观测` / `不适用`。后两者**退出分母**。报告写成 `就绪度 X / 可观测满分 Y`，档位按归一化百分比判定。
4. **门槛项**：三项 `g.` 开头的检查照常计分，同时是封顶条件——但只在其中某项**得 0 分**时触发。得 0 分意味着爬虫真的拿不到内容，此时**归一化分**封顶 40%（封的是百分比，不是原始分），并在报告首屏置顶为 P0。中间档意味着够用但不够好，那是扣分，不是封顶。对「没拿满分」就封顶，正是 v1.0 把技术上没问题的站判成「危急」的原因。
5. **加分项**：四项 `b.` 开头的检查不进分母，只加到分子上，封顶 +6。它们不分档，只有做到与没做到。这些约定采纳率仍低，做了是领先，没做不扣分。
6. **看实质不看格式**：标题是否匹配提问意图，看的是「人会不会这么问」，不是有没有问号；时间信号看的是「读者与爬虫能否确认时效」，schema 日期与页面可见日期等效。
7. **中文站**：自足答案段按 50–200 汉字判定（英文为 25–120 词）。这个换算是本量表的约定，必须写进报告的 evidence。
8. **证据**：每一项都要留可复核的观察——状态码、字节数、命中或未命中的那一句。没有证据的判定不成立。

## 档位

| 归一化分 | 档 | 含义 |
|:-:|---|---|
| 83+ | **领先** | 已建立优势，重点转向维持与扩大 |
| 66+ | **基础扎实** | 地基完备，缺口集中在内容深度与品牌资产 |
| 51+ | **成长期** | 主要项目已在做，差的是系统性与一致性 |
| 31+ | **起步期** | 基础项有明显缺口，其中多数可在数人天内补齐 |
| 0+ | **未起步** | 尚未针对 AI 检索做过建设，提升空间最大 |

档位线取自 GW Content 公开的 AEO 阶梯，该阶梯有其自述的真实分布背书（「多数商业网站落在 30–55」）。档名描述的是**所处阶段，不是判决**——这是一份用来决定下一步做什么的诊断。

## 这份量表不告诉你怎么修

每一项只说**测什么**、**分几档**、以及**为什么这项对被检索重要**。具体修法、工作量估算、承担角色与修复排序不在本仓库——见 README 的边界说明。这条线是刻意的：一份量表要可复核就必须公开判据，而判据公开不等于实施方案公开。

## 报告形态

- **排序**: 首屏的三处缺口按可回收分数排序；门槛项未拿满时永远排第一，因为在爬虫拿不到内容之前，其余各项的改动都不会产生效果。
- **首屏**: 首屏三样：当前分与所处档、距下一档还差几分、以及最大的三处缺口。完整清单必须同时给出，放在首屏之后。
- **每条失分**: 每条失分固定三段：为什么重要、当前落在哪一档、上一档要求什么。「怎么修」与工期属于实施层，不在本量表范围内。

## 可被抓取 · 15 分

### robots 放行检索爬虫 · 5  `g.robots`

唯一一条「没做到，后面全部白做」的检查。爬虫被挡住时，站内做得再好也进不了 AI 的答案。

| 分 | 判据 |
|:-:|---|
| 0 | 对检索类 UA 设了 Disallow |
| 3 | 没有适用于检索 UA 的 Disallow，但也没有任何 Allow 指令 |
| 5 | 检索 UA 被明确放行——逐个具名 Allow，或 User-agent: * 下有 Allow: / 且无适用的 Disallow |

> 门槛项：计分，同时是封顶条件。任一门槛项**得 0 分**时，**归一化分**封顶 40%（封的是百分比，不是原始分），并在报告首屏置顶为 P0。封顶只在真的拿不到内容时触发——中间档意味着够用但不够好，那是扣分，不是封顶。

### 检索 UA 实测可达 · 5  `g.reachable`

robots.txt 写了放行不等于真拿得到——CDN 与 WAF 常按 UA 拦截，这一层只有实测看得见。「内容一致」指正文文本一致，按去掉空白后的正文比对，不按原始字节——CSRF token、nonce、时间戳的差异不算不一致。

| 分 | 判据 |
|:-:|---|
| 0 | 多数检索 UA 被拦 |
| 3 | 1–9 个 UA 返回 200，或正文与浏览器所见不一致 |
| 5 | 10 个 UA 均 200，且正文与浏览器所见一致 |

> 门槛项：计分，同时是封顶条件。任一门槛项**得 0 分**时，**归一化分**封顶 40%（封的是百分比，不是原始分），并在报告首屏置顶为 P0。封顶只在真的拿不到内容时触发——中间档意味着够用但不够好，那是扣分，不是封顶。

## 可被理解 · 22 分
