## 决议一览

| # | 问题 | v1.1 的决定 |
|:-:|---|---|
| 1 | 档名描述的是分数不是站点健康度 | 五档全部换成阶段语义（未起步／起步期／成长期／基础扎实／领先）；「危急」删除，CI 现在拦截判决式档名。同时把「就绪度」与「引用表现」拆成两个数——36 分刺眼的根因是把可修的和天然低的搅在一起 |
| 2 | `llms.txt` 的「分节链接组」是否要求该节含链接 | **要求含链接**。阶梯第 3 档写死「2 个以上**含链接**的主题分节」，无链接的散文分节不计入 |
| 3 | `llms-full.txt` 允不允许放在非根路径 | **允许**，但须可从 `llms.txt` 或 `robots.txt` 发现。同时该项移出分母，改为加分项 |
| 4 | 「具名作者」是否强制要求站内 bio 页 | **不强制**。阶梯第 3 档为「姓名链向可核实的身份页」，站内作者页或本人主页等效 |
| 5 | 日期可见但无 `dateModified` 算不算时间信号 | **算**。schema 日期与页面可见日期等效，二者其一即可得中间档；两者一致才给满分 |
| 6 | 「40–90 词」在中文没有权威换算 | 定为**中文 50–200 字**（英文同时放宽到 25–120 词），写进量表第 7 条规则，不再由审计者各自决定 |
| 7 | 站点声明 0 个 `sameAs` 时是 failed 还是 not_applicable | **记 0 分，不退出分母**。没声明就是没做，不是不适用 |
| 8 | `robots.txt` 里声明的 sitemap 路径是否优先 | **优先于约定路径**，写进 `p1.sitemap` 的判据 |
| 9 | 活在子路径上的站（GitHub 项目页、`example.com/docs`、`brand.com/de/`）被一个它无权写入的原点根扣分 | **原点没有就退回到给定路径去找**。两处都有时原点优先，证据行注明读的是哪一处。涉及 `p1.llms-txt`、`p1.sitemap`、`b.llms-full`、`b.ai-txt`。`robots.txt` 保持只看原点——它按规范就是原点作用域，子路径站确实没有自己的一份，这个不对称是真实的，不是可修的 bug |

第 9 条在实现时还牵出两处原来没想到的：`p1.breadcrumb` 从原点数路径段，
于是项目页的每个网址都被当成嵌套页，再因为没有面包屑被扣分——现在改为相对给定路径计算，
且完全没有嵌套页的站退出分母而不是记 0；`p1.page-type` 的白名单里漏了 `Dataset`，
整类发布数据的站点（开放数据门户、科研与政府发布）被无声扣分。加 `Dataset` **没有重跑榜单**：
抽查了 8 个把这条列为最大缺口的站，没有一个用 `Dataset`，所以已公布的中位数不变，
但下次全量重跑可能会让少数发布数据的站升分。

其中第 1、6 两条改变的不只是判定，也改变了分数的含义：
第 1 条重新定义了分数说的是什么，第 6 条让中文站与英文站在内容支柱上第一次可比。

## 10 · 读不到的 robots.txt：算放行，还是算全禁？（待 v1.2 决定）

RFC 9309 把「读不到」分成两种。返回 4xx 表示没有这个文件，爬虫可以抓取任何内容（第 2.3.1.3 节）；
服务器出错、或网络拿不到任何响应，表示文件不可达，爬虫必须按全站禁止处理，直到能再次读到文件（第 2.3.1.4 节）。

geo-score 1.5.0 不执行 2.3.1.4：每次重试都返回 429 或 5xx 的 robots.txt，`g.robots` 仍给中间档，
证据写明状态码和重试次数；始终拿不到响应（超时、连接被断开）的 robots.txt 记为「不可观测」、退出分母——
网络够不着一个文件，不能当作这个文件写了什么的证据。

**留给 v1.2 的问题：** 每次重试都返回 5xx 的 robots.txt，是否应该像遵循 RFC 的爬虫那样按全站禁止处理，
即第 0 档并触发门槛封顶？反方理由：一次审计只看到一个时刻，而爬虫会在更长的时间里反复重试，之后才按故障处理。
v1.1 不做改动。

## 11 · 样本里没有一页带三个数字：给 7 分中的 3 分，还是不适用？（待 v1.2 决定）

`p2.sourced-stats` 只看样本中带三个或以上数字的页面。从 geo-score 1.5.0 起，一个数字只有在它所在的正文块、
或紧接着的下一块里有出处时才算有来源：指向站外来源的链接、`<cite>`、来源用语，或一个脚注引用、且页内对应的注释链向来源。
页面框架（页头、导航、页脚、侧栏）不读。年份、版本号、编号（七位及以上的连续数字，或 `京ICP证030173号` 这类备案号、账号）
和价格（按价格写法写的金额，如 `$29/mo`、`68元/月`，或单独成为价格卡片、价目表一格的金额，如 `£12 a month`）不算数字。
一页里超过一半的数字有出处，就算这一页「多数数字有出处」。
最高档要求四分之三的这类页面多数数字有出处且带链接，次一档要求一半的页面多数数字以上述任一方式有出处，
0 分以上的最低档只要有一个数字有出处。

样本里没有一页带三个数字时，这一项仍给一直以来的 3 分：没有可标注的，也就没有缺的，但也什么都没有展示。

**留给 v1.2 的问题：** 没有一页带三个数字的样本，是否应像没有抽到嵌套页时的 `p1.breadcrumb` 那样退出分母
（`not_applicable`）？赞成：样本里没有数字却得 7 分中的 3 分，读的是「什么都没有」。
反对：不陈述数字的站点没有提出需要读者核对的主张，量表也不把「没有主张」算作缺口。v1.1 不做改动。

## 候选诊断：只报告，不计分（2026-10-15 提出）

下面五项是我们考虑放进报告[分数之外](../cli/README.zh-CN.md#分数之外)一栏的观察；那一栏里已经有按页面读的 robots.txt、
服务器 HTML 里的链接和 hreflang。写代码之前先记在这里，设计可以公开讨论。

每一项都守那一栏已有的规矩：

- **不进任何档位、分数和分数段。** 量表 v1.1 不变，分数不动。要把其中哪一项变成计分的检查项，就是改量表，
  要像上面的待定问题一样公开讨论，作为新的量表版本发布。
- **随正常版本发布，带离线测试：** 下面每一种读法各一个样例站，再加一条测试，确认有没有这项观察分数都一样，
  hreflang 和 robots.txt 那两项观察就是这么测的。
- **要新增的请求是有意加的。** 第 12 项的前两种读法、第 15、16 项只读这次运行已经抓到的页面；第 12 项的第三种读法、
  第 13、14 项要自己发几个请求，`test_no_request_is_sent_twice` 给样例站定的请求数要跟着上调（见 [AGENTS.md](../AGENTS.md)）。
- **门槛是我们定的，可以调。** 哪一项在某个数之上告警、而这个数没有厂商公布，报告就照直写明，这个数做成用户能改的参数。

| # | 候选 | 新增请求 | 依据 |
|:-:|---|:-:|---|
| 12 | canonical：没有、全部指向首页、或带跟踪参数时不指向干净网址 | 0，第三种读法 1 | 厂商文档 |
| 13 | 软 404：随机路径回 200 | 2 | 厂商文档 |
| 14 | 首页按语言跳转 | 2 | 厂商文档 |
| 15 | 同一个套餐在两页上价格不同 | 0 | 实地观察 |
| 16 | 首页 HTML 体积（优先级较低） | 0，查资源另计 | 厂商文档与实地观察 |

### 12 · canonical

**会报告什么。** 从服务器 HTML 里的 `<link rel="canonical">` 和 `Link` 响应头读规范网址，分三种读法：

1. 抽样页里完全没有声明 canonical 的页面。
2. 样本里每一页都把首页声明为自己的 canonical，而这些页是网址不同、内容不同的页。
3. 在首页网址后加上 `?utm_source=chatgpt.com` 再请求一次，返回的 canonical 仍带着这个参数，而不是干净的网址。
   跳转到干净网址算通过。

**依据。** Google 把 `rel="canonical"` 列为决定几个重复网址里哪一个成为规范网址的强信号
（[合并重复网址](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)）。
OpenAI 的发布者常见问题写明，ChatGPT 搜索发出的链接会带 `utm_source=chatgpt.com`
（[Publishers and developers FAQ](https://help.openai.com/en/articles/12627856-publishers-and-developers-faq)），
所以一个在那里被引用的页面，也会以第二个网址被访问。每一页的 canonical 都指向首页，等于告诉爬虫内页都是首页的副本。

**误报风险：中等。** 用 JavaScript 插入的 canonical 不在服务器 HTML 里：报告会写「服务器 HTML 里没有」，不写「缺失」。
确实只有一页的站、系列分页指向整个系列的总览页、迁移期间或转载副本把 canonical 指向另一个域名，这些都是有意为之。
按查询串分别缓存的站，带参数的请求可能因为与页面无关的原因得到不同的回答。

**怎么测。** 样例站：每页 canonical 指向自己（干净）；每页都指向 `/`；把查询串原样写进 canonical 的页；带参数的网址跳转到干净网址；
canonical 只放在 `Link` 响应头里。手工：在首页网址后加 `?utm_source=chatgpt.com` 请求，看返回的 HTML 里 `rel="canonical"` 那一行。

### 13 · 软 404

**会报告什么。** 两个没有任何地方链接的随机路径，各请求一次：回 404 或 410、跳转到首页，还是回 200 和一个 HTML 页面。
两个都回 200 才算这一项的读数。

**依据。** Google 把软 404 定义为：返回一个告诉用户「此页不存在」的页面，状态码却是 200 的网址，并说这类页面会被排除在搜索之外
（[软 404 错误](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors#soft-404-errors)）。
对所有路径都回 200 的站，站点地图或回答里拼错的链接看起来也像真页面。CLI 在一个路径上已经遇到过同样的情况：
`p1.llms-txt` 把 `/llms.txt` 上回 200 的 HTML 读作兜底路由，不当作文件。

**误报风险：中等。** 未知路径上返回的机器人验证页不是页面，必须先跑现有的验证页识别。在浏览器里渲染「未找到」视图的单页应用
本来就回 200：这正是读数，但报告要写明这是应用外壳。限流可能用一个错误页回应探测请求。用两个路径、两者一致才出读数，
免得一次偶然的回答说了算。

**怎么测。** 样例站：真 404；回 200 的兜底路由；把未知路径跳转到首页；未知路径上返回验证页。手工：请求
`/this-page-should-not-exist-7f3a` 这样的路径，只看状态码。

### 14 · 首页按语言跳转

**会报告什么。** 除了每次运行已经发的 `Accept-Language`（`en,zh;q=0.8`），再用两个不同的值请求首页，看最终网址是否不同。
对所有语言都一样的跳转（根路径总是去 `/en/`）不算这一项。

**依据。** Google 说 Googlebot 的请求通常来自美国的地址、不设置 `Accept-Language`，所以可能找不到每一种语言版本，
并建议不要按推测的用户语言自动跳转
（[多区域和多语言网站](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)、
[按语言区域自适应的网页](https://developers.google.com/search/docs/specialty/international/locale-adaptive-pages)）。
落在某一个语言版本上的检索爬虫，可能永远看不到其他版本。站点交回另一个源时，CLI 已经记录请求最终落在哪里，
那是同一个现象在一个请求头下的样子。

**误报风险：中等，而且有盲区。** 按 IP 地址跳转从一个地点看不出来：报告只能说审计者的地址拿到了什么，说不了别处的爬虫拿到什么。
同一个网址按请求头返回不同内容、不跳转，是另一种读数（`Vary: Accept-Language`）；同意弹窗或地区墙也可能因为与语言无关的原因跳转。

**怎么测。** 样例站：按 `Accept-Language` 选择跳转目标；所有请求都跳到 `/en/`；同一网址按请求头返回不同内容、不跳转。
手工：分别带 `Accept-Language: de` 和 `Accept-Language: en` 请求首页，比较两次的 `Location` 响应头。

### 15 · 同一个套餐在两页上价格不同

**会报告什么。** 同一个套餐或产品名，在两个抽样页上（比如定价页和某个文档页、常见问题页）以同一币种、同一计费周期出现了不同金额，
引用两处金额和两个页面。

**依据：实地观察。** 回答引擎按它取回的那一页做摘要。同一个站的两页说法不一致，同一个问题就会得到两个不一致的回答，
引擎也无从判断哪一个是现行的。没有厂商把这一点写成引用的因素。CLI 已经能认出价格（`p2.sourced-stats` 计数字时排除价格，
见本页上面第 11 条）。

**误报风险：高，** 所以它只会并排引用两段原文，不下结论。月付和年付、分地区的价格和币种、划线原价旁边的新价、含税与不含税、
按席位和按固定价、阶梯量价、更新日志或博客里带日期的旧价格、示例里的价格，看起来都像不一致，其实都不是。
8 页的样本里也很少同时有两页给同一个套餐标价，所以没有读数说明不了多少。

**怎么测。** 样例站：价格一致；一处真正的不一致；月付和年付成对出现；划线原价。手工：把每一页上写到的每个套餐价格列成一张表。

### 16 · 首页 HTML 体积（优先级较低）

**会报告什么。** 首页 HTML 传输时和解压后的大小；之后再加首页 `<head>` 引用的样式表和脚本的大小；超过门槛时告警。

**依据。** Google 的文档写明，为 Google 搜索抓取时，Googlebot 读取受支持文件类型的前 2 MB，页面引用的每个资源单独抓取、
适用同样的上限（[Googlebot](https://developers.google.com/search/docs/crawling-indexing/googlebot)，2026-10-15 读取）。
超过上限的内容不会被读到。从业者还说过页面涨到很多兆之后整站掉出搜索索引的例子；那是个案，没有厂商为此公布数字，
低于文档上限的任何告警线都只是从业者的经验值：可以调，不是厂商的数字。

**误报风险：测量本身低，告警高。** 大小取决于用户代理和压缩；内联 SVG、字体和 data URI 会合理地撑大 HTML；
很大的序列化状态对象是实实在在的成本，但不是错误。查资源大小每个都要一次请求，所以会设上限。

**怎么测。** 样例站：小页面；内联了一大块数据、超过门槛的页面；同一页以 gzip 返回，算解压后的大小。手工：开着解压下载首页，数字节数。
