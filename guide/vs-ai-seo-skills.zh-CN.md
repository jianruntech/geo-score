# geo-score 和通用 AI SEO 技能有什么不同

AI SEO 技能是写给编程智能体的一套指令：让模型读一个网站，对照清单做判断、给出修改建议，常常还直接动手改。
geo-score 是一套公开的打分规则，加上实现它的程序。两者回答的问题不同，可以配合使用。本页不点名任何别的项目，只比较这两类工具。
English: [vs-ai-seo-skills.md](vs-ai-seo-skills.md)

| | 通用 AI SEO 技能 | geo-score |
|---|---|---|
| 是什么 | 模型照着做的指令 | 带版本号的量表（[v1.1](../rubric/v1.1.zh-CN.md)）和实现它的程序，只用标准库 |
| 读数由谁定 | 模型，依据它碰巧读到的页面 | 量表：21 项检查，每一档写成 8 个抽样页里的页数 |
| 同一个站再跑一次 | 取决于模型、提示词和当天 | 同样的页面得到同样的分；重新抽样会差多少，在 [REPRODUCIBILITY.md](../benchmark/REPRODUCIBILITY.md) 里实测过 |
| 看到什么 | 智能体自己的抓取工具拿到的东西 | 按 RFC 9309 读 robots.txt，以 10 个检索爬虫和浏览器的身份分别请求页面，读 JavaScript 执行之前的服务器 HTML |
| 证据 | 一段文字 | 每项检查一行证据（`--explain`），JSON 报告符合[公开的 schema](../schema/report.v2.json) |
| 看不到的部分 | 通常不说 | 退出分母并写明，从不记 0 分 |
| AI 有没有引用你 | 通常不测，或者只问一次 | 第二、三级用你自己的 Key 通过各家 API 去问，报告带区间的比例，从不加进分数 |
| 修复 | 常常直接写 | 不写，只有[两个公开样例](public-examples.zh-CN.md)例外 |
| 花费 | 模型用量 | 第一级免费；第二、三级花的是你自己的 API 调用 |

## 技能更擅长的事

写。把一段话改成能单独成立的样子、起草常见问题、建议更贴近用户提问方式的标题、调整语气：这些是判断和手艺，
有好指令的模型是合适的工具。量表自己也有三项检查（`p3.listings`、`p3.mentions`、`p4.question-coverage`）需要站外搜索或人的判断，
所以 geo-score 也以智能体技能的形式发布（[SKILL.md](../SKILL.md)），由智能体完成这几项，并照直写明。

## 提示词里的清单保证不了的事

- **可比。** 依赖模型的读数，没法和上个月比，也没法和竞争对手比。带版本号的量表可以：每份报告写明量表版本，不同版本的分数不放在一起比。
- **爬虫的视角。** 模型抓页面，看到的是它自己的抓取工具拿到的东西。只拒绝某一个检索爬虫的防火墙，或者正文要等 JavaScript 跑完才出现的页面，
  从那个视角看都没有问题。
- **能复算的数字。** 每一项检查、每一档和每个权重都是公开的，任何人都能用同样的页面复算 geo-score 的结果，手工
  （[rubric/README.md](../rubric/README.md#how-to-score-without-the-skill)）或者用另一种实现都可以。

## 两个一起用

改之前打一次分，用合适的工具或人去改，再在同样的页面上打一次分：`--baseline before.json` 重读第一次运行的页面，
逐项列出哪里变了（[cli/README.zh-CN.md](../cli/README.zh-CN.md#对比两份报告)）。怎么改可以换，测量保持不变。
