# 常见问题排查

本页解释工具的行为和读数，不讲怎么改网站。English: [troubleshooting.md](troubleshooting.md)

## 两次运行分数差了几分

**原因。** 每次运行从 sitemap 和首页链接里最多抽 8 个页面，每次抽到的不完全一样：某页 404 了、sitemap 顺序变了、
链接轮换了。实测波动约 ±5 分，见 [REPRODUCIBILITY.md](../benchmark/REPRODUCIBILITY.md)。

**怎么办。** 固定抽样页面。第一次用 `--json-out before.json` 保存，之后用 `--urls-from before.json` 重评。
第二次读的是完全相同的页面，分数的差异就来自网站本身。在 CI 里，`--fail-under` 至少比平时的分数低 5 分。

## 某个检查项显示 `—` 而不是分数

**原因。** `—` 表示「未测」，未测的项移出分母，而不是记 0 分。分两种：

- `p3.listings`、`p3.mentions`、`p4.question-coverage` 需要站外搜索或人工判断，CLI 从不给它们打分，人工审计才打。
- `p3.knowledge-graph`、`p3.sameas`、`p1.breadcrumb`、`p4.cn-engines` 在本次运行观测不到时显示 `—`：Wikidata
  或 Wikipedia 没有响应、主页资料链接超时、抽到的页面都不是嵌套页，或者这不是中文站。

**怎么办。** 第一种不用管。第二种，换一个能访问 Wikidata 和 Wikipedia 的网络重跑（见下文「代理」）。
报告里的 `reason` 字段写明了是哪种情况；终端报告的页脚也把两种分成两行列出：`Needs off-site search or judgement:` 和
`Not observable this run:`，后者每一项都附一句简短的原因。

## 分数被封顶在 40（有门槛项得 0 分）

**原因。** 三个门槛项（`g.robots`、`g.reachable`、`g.ssr`）中有一项得了 0 分，意味着检索爬虫根本拿不到内容。
只有得 0 分才封顶；中间档是普通扣分。

报告开头会点名每个得 0 分的门槛项，并附上其证据的第一句（`GATE AT ZERO — g.ssr: …`），*Biggest gaps* 也以该门槛项打头。

**怎么办。** 用 `--explain` 看该门槛项的证据。`g.reachable` 是最不稳定的一项：防火墙或反爬服务对十个检索 UA
的响应可能前后一分钟就不同，下结论前先重跑。它的探测是从你自己的地址发出厂商的 UA 字符串，按 IP 段核验爬虫的防火墙
可能拒绝这些探测、却照常放行真正的爬虫（见 [reference/ai-crawlers.md](../reference/ai-crawlers.md)）。

**在 CI 里。** 门槛项得 0 分时分数正好封顶在 40，所以 `--fail-under 40`（Action 里是 `fail-under: 40`）永远拦不住被封顶的站；
请加上 `--fail-on-gate`（`fail-on-gate: true`）。`--assert` 可以把单个检查项锁在某一档，例如 `g.robots=max`。
对启发式检查项的断言带着和总分一样的逐次波动，断言这类检查时请用 `--urls-from` 固定页面。

## `could not fetch …`，退出码 2

**原因。** CLI 请求的东西没有一个作为可评分的页面返回。报错信息在括号里写明失败的类型，例如
`could not fetch https://example.com (timeout): …`，并链接到下面对应的小节。域名解析不了、连接被拒绝、TLS 握手失败
都不重试，一秒内就会报错；超时和连接中断会各试三次。每个页面都返回人机验证页的网站也以退出码 2 结束，报错为
`bot challenge served to a browser user-agent (…)`（类型 `bot_challenge`，见下文）。退出码 2 也用于参数错误（包括不是网址的输入）、
被拒绝的 `--urls` 列表和内部错误。

加了 `--json` 时，退出码 2 会在 stdout 输出一个 JSON 错误，而不是报告（[`schema/error.v1.json`](../schema/error.v1.json)）：
`error.kind` 就是同一个类型标记，流水线不用读报错文字，就能分清是域名打错了还是网站拒绝了这个工具。

**怎么办。** 看对应类型的小节。在同一台机器上确认 `curl -I https://该站点/` 能通。在代理后面，设置 `HTTPS_PROXY`；
请求经过代理时，报错会写明是哪个代理，因为失败可能出在代理那里。

### dns：域名解析不了

**原因。** 这个主机名没有地址：拼写错误、域名已过期，或者所用的 DNS 服务器或 VPN 看不到它。没有代理时，CLI 在抓取
任何东西之前先解析一次域名，所以会立刻报错。请求经过代理时，由代理去解析域名，这一步检查会跳过。

**怎么办。** 检查拼写。在同一台机器上运行 `nslookup 该主机`，可以看到 DNS 的回答。如果所在网络只能通过代理解析域名，
设置 `HTTPS_PROXY`。

### refused：连接被拒绝

**原因。** 主机有地址，但那个端口上没有东西接受连接：服务器没开、网址里的端口写错了，或者防火墙拒绝了连接。

**怎么办。** 检查网址里的端口（除非网址另写端口，`https://` 用 443，`http://` 用 80），再从别的网络确认网站是否在线。

### tls：HTTPS 握手失败

**原因。** Python 没能建立 HTTPS 连接：证书无效、过期或签给了别的域名，服务器只提供 Python 拒绝的协议版本，或者
本机和网站之间有东西（代理、杀毒软件或公司防火墙）干扰了 HTTPS。在代理后面，一个不存在的主机也可能表现成这样：
有些代理先接受连接，连不上目标主机时再把连接关掉。

**怎么办。** 报错里写了代理时，先检查拼写。然后在同一台机器上用浏览器打开网站。CLI 用 Python 自己的证书库核验证书，
它可能和浏览器用的不一样。

### timeout：没有按时回应

**原因。** 三次尝试中，服务器每次都没在 `--timeout` 秒内回应（默认 15 秒）。超时会立即重试，因为等待的时间已经花掉了。

**怎么办。** 重跑。网站在线但很慢时，可以把等待时间调长，例如 `--timeout 40`。如果每次都超时，在同一网络里用
`curl -I` 检查网站。

### dropped、no_response：没有收到回应

**原因。** 连接在 HTTP 回应到达之前就断了（`dropped`），或者收到的不是 HTTP（`no_response`）。防火墙和反爬服务会这样
对待它们不信任的客户端，负载过高的服务器也会。两种情况都会各试三次。

**怎么办。** 过一会儿重跑，并和同一台机器上 `curl -I` 的结果对比。连不上网站的代理也可能直接关掉连接；请求经过代理时，
报错会写明是哪个代理。

### http_NNN：页面返回了 HTTP 错误

**原因。** CLI 请求的每个页面都返回了 HTTP 错误。类型标记用的是第一个页面的状态码，例如 `http_403`（常见于防火墙或
反爬服务拒绝非浏览器客户端）、`http_404`（路径不存在）、`http_429`（限流）或 `http_503`；报错信息会列出看到的所有状态码。

**怎么办。** 检查网址，包括其中的路径。如果浏览器能打开、CLI 却拿到 403，就是网站拒绝了这个工具；只要有页面能加载，
这种差别正是 `g.reachable` 要测的东西。

### no_content：页面返回为空

**原因。** 服务器返回了成功状态码，但正文是空的。

**怎么办。** 检查网址，再和同一台机器上 `curl -i` 的结果对比。

### slow：回应一直没传完

**原因。** 服务器传回应的速度太慢，一次请求（含重定向）超过了单次请求的上限：30 秒，或者 `--timeout` 的两倍（取较长者）。
有些网站会故意这样对待爬虫。传得太慢的回应不会重试。

**怎么办。** 过一会儿重跑。如果同一网络里浏览器很快就能打开页面，说明网站在拖慢这个客户端，真正的爬虫也可能遇到同样的情况。
把 `--timeout` 调长会同时放宽单次请求的上限。

### deadline：这次运行超时了

**原因。** 一次运行最多 300 秒。到点后不再发起新请求，进行中的请求也会停下。出现这个报错，说明到那时还没有任何可评分的页面返回；
如果已有页面返回，运行会照常结束，缺了回应的检查项显示为不可观测。

**怎么办。** 过一会儿重跑，或者用 `--sample` 或更短的 `--urls` 列表少评几个页面。

### bot_challenge：返回的是人机验证页，不是网站内容

**原因。** 反爬服务（AWS WAF、Akamai、Cloudflare、Fastly、PerimeterX、DataDome 或 Imperva）给 CLI 的浏览器 UA
返回了人机验证页，只有执行其脚本的浏览器才能通过。报错信息会写明认出的是哪家的验证页。验证页不是网站的内容，所以从不评分：
如果当成内容来读，`g.ssr` 会记 0 分，网站会因为一个它未必有的 JavaScript 问题被封顶。抽样页面里只有一部分是验证页时，
运行会给其余页面评分，报告的 notes 会写明 `Scored on N of M sampled pages; …`。带有实质正文的页面照常评分，不管它还加载了什么反爬脚本。

**怎么办。** 工具里没有办法绕过验证页：静态抓取能看到什么，它就测什么。同一套防护对待真正的检索爬虫可能和对待这台机器不同
（按地址、信誉或已核验爬虫名单），所以这既不说明 AI 爬虫能拿到内容，也不说明拿不到。换一个网络重跑，结果可能不同。

## 代理

CLI 使用 Python 的标准代理设置：`HTTPS_PROXY`、`HTTP_PROXY` 和 `NO_PROXY`（macOS 和 Windows 上还会读系统代理）。
在无法直连 Wikidata、Wikipedia 或部分社交主页的网络里，`p3.knowledge-graph` 和 `p3.sameas` 会显示为未测，而不是 0 分。
设置代理后重跑即可测到。

## 报告评的不是我输入的那个域名

**原因。** 网站做了跳转：跳到 `www.`、跳到语言路径，或者跳到另一个域名。报告会写明最终落在哪里。

**怎么办。** 直接评你想测的那个地址。如果网站在某个路径下（`example.com/docs`），就给出这个路径；
抽样会限定在路径内，而 `robots.txt` 和 `llms.txt` 仍在域名根目录读取，因为规范规定它们在那里。

## 我的分数和公开榜单对不上

**原因。** 榜单是某一天的测量结果：当前这一轮是 2026-09-27 用 1.3.0 跑的，317 站有分。那之后网站页面可能变了，
每次抽到的页面也不同，而旧版工具出的报告对部分检查项的读法不一样（见更新日志）。每份报告都写明了工具版本（`tool`），
这一轮每个站的完整报告在 `benchmark/raw/`。

**怎么办。** 只比较同一工具版本得出的分数，并记住 ±5 的波动。想看榜单读到的到底是什么，打开 `benchmark/raw/` 里那个站的文件，
再用 `--urls-from` 指向它，在同一批页面上重评。

## `watch` 或 `--ask` 提示需要 `geo_watch.py`

**原因。** 第二、三级在 `cli/geo_watch.py` 里。一行命令 `curl … | python3 -` 只运行第一级，
而且从不加载当前目录下的 `geo_watch.py`。

**怎么办。** 从发布的 wheel 安装工具
（`pipx install https://github.com/jianruntech/geo-score/releases/download/v1.4.0/geo_score-1.4.0-py3-none-any.whl`；
从源码安装需要 git：`pipx install git+https://github.com/jianruntech/geo-score@v1.4.0`），或者克隆仓库，
或者从同一个版本下载 `cli/geo_score.py` 和 `cli/geo_watch.py` 放在同一个文件夹。两个文件的版本必须一致。

## `watch run` 退出码 3

**原因。** 一个引擎都没测成。要么没有设置 API Key，这时什么都不运行、什么都不记录；要么所有调用都失败了
（Key 被拒、额度用完、网络错误），这时运行文件照常保存并写明每个引擎的错误，退出码表示其中没有任何测量结果。

**怎么办。** 运行 `geo-score watch check` 看哪些引擎设置了 Key。调用失败的情况，打印出的报告和保存的运行文件里
都写明了每个引擎的错误。Key 只从环境变量读取。

## GitHub Action 显示的注释比 0 分项少

**原因。** GitHub 每一步每种级别最多显示 10 条注释。其余的由 Action 列在任务摘要里。

**怎么办。** 看任务摘要，或者把 SARIF 文件上传到代码扫描，那里没有这个限制。`upload-sarif` 需要在任务权限里
设置 `security-events: write`。

## 中文站按字数算，英文站按词数算

**原因。** 只要抽到的页面里有一个页面的可见文字以中文为主，整次运行的长度阈值就从词数换成字数（例如答案段落是
50–200 字，而不是 25–120 词），并且 `p4.cn-engines` 变为可测。一个中文页就够了：双语网站只要抽到一个中文页，
所有页面都按中文阈值判定。报告里的 `audience_language` 写明了走的是哪一支。

**怎么办。** 检查抽到了哪些页面（`sampled_urls`）。想按英文阈值评双语网站的英文版，用 `--urls` 只指定英文页；
想评中文版，就只指定中文页。
