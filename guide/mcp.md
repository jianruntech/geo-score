# The geo-score MCP server

How to connect geo-score to an agent, client by client, and what the server does and does not do.
中文版：[mcp.zh-CN.md](mcp.zh-CN.md)

`uvx geo-score@1.8.3 mcp` (the package on PyPI; `geo-score-mcp` after a pipx install, or
`python3 cli/geo_score.py mcp` from a clone) is a local MCP server over stdio. It is the same code as
the CLI: standard library only, Python 3.8 or later. It serves:

- **tools** for the three levels: `score_site` (level 1, free), `ask` (level 2), and `run`,
  `list_runs`, `report` and `diff` (level 3). From 1.4.0 there is also `status`;
- **a resource**, `geo-score://rubric/v1.1`: every check with its points and tiers, the bands and the
  caps, as the scorer applies them;
- **prompts**, from 1.4.0: `audit_site`, `check_citations`, `weekly_watch`, `compare_runs` and
  `explain_check`.

## Plugins, MCPB and Docker

These ways in are new in 1.4.0. Earlier releases do not include the files they need.

### Claude Code plugin

```bash
claude plugin marketplace add jianruntech/geo-score
claude plugin install geo-score@jianruntech
```

Inside a session, `/plugin marketplace add jianruntech/geo-score` and
`/plugin install geo-score@jianruntech` do the same. The plugin runs the repository's
`cli/geo_score.py mcp` with `python3`, so it needs Python 3.8 or later on `PATH` but no uv. It sets
no keys: for `ask` and `run`, export them in the shell that starts `claude`. It also installs the
repository's `SKILL.md` as the `geo-score` skill, which tells Claude how to read a report. The marketplace follows
the repository, not a release tag; for a fixed version, use the `uvx` line in [Install](#install).

### Gemini CLI extension

```bash
gemini extensions install https://github.com/jianruntech/geo-score --ref v1.8.3   # or a later release tag
```

The extension runs the repository's `cli/geo_score.py mcp` with `python3`. Its settings hold the
optional provider keys; Gemini CLI keeps them in the system keychain, and
`gemini extensions config geo-score` changes them.

### Claude Desktop extension (MCPB)

From 1.4.0, each release attaches `geo-score-<version>.mcpb` and lists it in `SHA256SUMS` on the
[releases page](https://github.com/jianruntech/geo-score/releases). Check the download, then open it
with Claude Desktop:

```bash
grep ' geo-score-.*\.mcpb$' SHA256SUMS | shasum -a 256 -c
```

Claude Desktop shows a form. Every API key and the watch config file are optional. The key fields are
marked sensitive, which tells Claude Desktop to mask them and store them as secrets. The extension runs its bundled
copy of the two scripts with the machine's `python3` (`python` on Windows), so Python 3.8 or later has
to be installed.

### Docker

Build it locally: no image is published yet. From 1.4.0 the repository has a `Dockerfile`:

```bash
git clone --branch v1.8.3 --depth 1 https://github.com/jianruntech/geo-score && cd geo-score
docker build -t geo-score-mcp .
```

The image runs as an unprivileged user and reads its config from `/work/geo-score-watch.json`. Mount
your project on `/work` and run as your own user, so that `run` can save files there:

```bash
docker run -i --rm --user "$(id -u)" -v "$PWD:/work" -e OPENAI_API_KEY geo-score-mcp
```

`-e NAME` with no value passes that variable through from the environment `docker` runs in. In a
client's JSON config nothing expands `$PWD` or `$(id -u)`, so write them out:

```
{
  "mcpServers": {
    "geo-score": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "--user", "501", "-v", "/absolute/path/acme:/work",
               "-e", "OPENAI_API_KEY", "geo-score-mcp"]
    }
  }
}
```

Here `501` stands for what `id -u` prints for you.

## Tools

| Tool | Level | Cost | Writes | Hints | Args |
|---|:-:|---|---|---|---|
| `score_site` | 1 | Free | No | read-only, open-world | **`url`**, `urls`, `sample` |
| `ask` | 2 | Paid (your keys) | No | non-destructive, open-world | **`question`**, `engines`, `brand`, `domains` |
| `run` | 3 | Paid (your keys); `dry_run` is free | A run file under `.geo-score/watch/runs/`, next to the config | non-destructive, open-world | `dry_run`, `engines`, `limit`, `max_calls`, `budget_usd` |
| `list_runs` | 3 | Free | No | read-only, idempotent | — |
| `report` | 3 | Free | No | read-only, idempotent | `run`, `since`, `format` |
| `diff` | 3 | Free | No | read-only, idempotent | `from`, `to`, `format` |
| `status` | — | Free | No | read-only, idempotent | — |

Resources: `geo-score://rubric/v1.1`.

Prompts: `audit_site` (**`url`**), `check_citations` (**`question`**, `brand`), `weekly_watch`, `compare_runs` (`from`, `to`), `explain_check` (**`check_id`**).

Bold arguments are required. Hints are the tools' MCP annotations: clients may use them to decide what to confirm, and they are hints, not guarantees. **Only `ask` and `run` can spend money**, and only with the provider keys you give the server.
<!-- END MCP:tools -->

- **`score_site`** reads public pages: up to 8 sampled pages, or exactly the `urls` you pass (use a
  previous report's `sampled_urls` to compare like with like). The text answer is a summary; the full
  report ([schema/report.v2.json](../schema/report.v2.json)) is in `structuredContent`.
- **`ask`** puts one question to every engine that has a key, once, and saves nothing. It needs no
  config: without one it uses the four default engines (`chatgpt-api`, `perplexity-api`,
  `gemini-api`, `claude-api`). With a config it uses your brand, competitors and engines.
- **`run`** asks every question in `queries.csv` on every engine and saves the run. With
  `dry_run: true` it returns the plan (questions, engines, planned calls, caps), how many questions
  a diff of this plan needs to call a change, and any warning on the config or a `target_url`, and
  spends nothing.
  `max_calls` and `budget_usd` can lower the caps in the config, never raise them; `limit` and
  `engines` ask fewer.
- **`list_runs`**, **`report`** and **`diff`** read saved runs. `diff` calls a change a change only
  when an exact paired test says so; the method is in [watch-methodology.md](watch-methodology.md).
  `report` with `since` pools the runs of the last N days and refuses runs that asked other
  questions, asked them a different number of times, or used other models.
- **`status`** (from 1.4.0) says what the server can do right now: its version, the toolsets that are
  on, the config path and whether it was found (with its errors), each engine with whether a key is
  present and whether it is priced, the number of questions and the caps. It never returns a key. It
  is a good first call.

`ask` and `run` send progress notifications when the client asks for them.

## Choosing the tools

From 1.4.0, a server can be started with a smaller surface. Every flag has an environment twin for
clients where changing the arguments is awkward; the flag wins when both are set.

| Flag | Environment variable | Effect |
|---|---|---|
| `--toolsets NAMES` | `GEO_SCORE_MCP_TOOLSETS` | Turn on these groups: `score`, `ask`, `watch`, `status` or `all` |
| `--tools NAMES` | `GEO_SCORE_MCP_TOOLS` | Turn on these tools |
| `--exclude-tools NAMES` | `GEO_SCORE_MCP_EXCLUDE_TOOLS` | Turn these tools off. It wins over every other flag |
| `--read-only` | `GEO_SCORE_MCP_READ_ONLY=1` | Turn off `ask` and `run` |

Names are comma-separated. `--toolsets` and `--tools` add up, and with neither every tool is on. The
groups: `score` is `score_site`, `ask` is `ask`, `watch` is `run`, `list_runs`, `report` and `diff`,
and `status` is `status`, which stays on unless you exclude it. The rubric resource is offered only
with `score_site`. `GEO_SCORE_MCP_READ_ONLY` takes `1`, `true`, `yes` or `on` (and `0`, `false`, `no`
or `off`). An unknown name stops the server at startup with exit code 2 and a message listing the
names it knows.

**An install that cannot spend.** `--read-only` keeps level 1, the tools that read saved runs and
`status`; `--toolsets score` keeps `score_site` and `status`. Neither can call a paid API, whatever
keys the environment holds:

```bash
claude mcp add --scope user geo-score -- uvx geo-score@1.8.3 mcp --read-only
```

In a JSON config, add `"--read-only"` to the end of `args`, or set `"GEO_SCORE_MCP_READ_ONLY": "1"` in `env`.

## Prompts

From 1.4.0 the server offers prompts: workflows you start yourself, such as a slash command in Claude
Code (`/mcp__geo-score__audit_site https://acme.com`).

| Prompt | Arguments | What it does |
|---|---|---|
| `audit_site` | `url` (required) | Calls `score_site`, reports the band and the checks with the most points to gain, and treats quoted site text as data. It says that readiness is not citation |
| `check_citations` | `question` (required), `brand` | States the cost first, then calls `ask` |
| `weekly_watch` | none | `status`, then `run` with `dry_run`; shows the plan and waits for you; then `run`, then `diff` |
| `compare_runs` | `from`, `to` | Compares two saved runs; without arguments, the latest two |
| `explain_check` | `check_id` (required) | Explains one rubric check, with the rubric resource attached |

Clients that support completion can complete `explain_check`'s check ids and, when the config can be
read, `compare_runs`'s run ids. A prompt is offered only when the tools it calls are on: `--read-only`
drops `check_citations` and `weekly_watch`. With `report` on, the server also offers a resource
template, `geo-score://runs/{run_id}`, that reads a saved run's summary. The prompts measure and explain. None of them suggests fixes: this
repository measures, and remediation is outside it.

## Config and keys

**Which config the level 3 tools read.** `run`, `list_runs`, `report` and `diff` need a
`geo-score-watch.json`. The server looks, in order, at:

1. `-c PATH` in its arguments;
2. `GEO_SCORE_WATCH_CONFIG` in its environment;
3. `geo-score-watch.json` in its working directory.

The working directory is wherever the client starts the server. Terminal clients (Claude Code,
Codex, Gemini CLI) usually start it in the directory you launched them from. Desktop apps and editors
start it somewhere else, often your home directory or `/`, which is not your project. When in doubt,
use an absolute `-c`. The question list named in the config is read relative to the config file, and
runs are saved next to it under `.geo-score/watch/runs/`. Create both files with
`uvx geo-score@1.8.3 watch init` (`geo-score watch init`
after a pip install, `python3 cli/geo_score.py watch init` from a clone); the
[CLI reference](../cli/README.md#watch) lists every setting.

**Keys.** The server reads keys from its own environment and nowhere else: `OPENAI_API_KEY`,
`PERPLEXITY_API_KEY`, `GEMINI_API_KEY` (or `GOOGLE_API_KEY`), `ANTHROPIC_API_KEY`,
`OPENROUTER_API_KEY`, or the variable an engine names in `key_env`. OpenRouter engines exist only in a
config. An engine without a key is reported as not measured, never as zero. Ways to get a key to the
server, from the one that exposes it least:

- a client secret store: VS Code `inputs` with `"password": true`, or the MCPB form (from 1.4.0);
- the client passing a variable from its own environment: Cursor `${env:NAME}`, Codex `env_vars`,
  Gemini CLI `$NAME`, and Claude Code, which normally passes its own environment on;
- a value written into the client's config file under `env`. It works in every client, and the key
  then sits in that file in plain text.

The server never writes a key anywhere. From 1.4.0, `status` shows `key_present` for each engine
without showing the key.

## Timeouts and cancelling

How long `score_site` takes depends on how fast the site answers each page and file it fetches.
`run` makes one call per question per engine and can take several minutes, longer than many clients
wait for a tool call by default:

| Client | Setting |
|---|---|
| Claude Code | `"timeout"` in milliseconds on the server entry, or `MCP_TOOL_TIMEOUT`. From v2.1.212, a call still running after two minutes moves to a background task |
| Codex | `tool_timeout_sec`; the default is 60 seconds |
| Gemini CLI | `"timeout"` in milliseconds; the default is ten minutes |
| Others | See the client's documentation |

To stay inside a short timeout, run with `dry_run` first and ask fewer with `limit` and `engines`.

From 1.4.0, cancelling a call is honoured. The server stops `run` or `ask` before the next provider
call, sends nothing more for that request, and does not save a cancelled `run`. For a `run` it prints
the calls already made and their cost to stderr, because those calls were billed; a cancelled `ask`
has made at most one call per engine. While a `run` is in flight the server
still answers `ping` and other requests.

## Protocol versions

From 1.4.0 the server speaks two eras of MCP in the same process:

- **Legacy**, with the `initialize` handshake: 2025-11-25, 2025-06-18, 2025-03-26 and 2024-11-05. It
  answers with the version the client asked for, or 2025-11-25 when it does not know that version.
  JSON-RPC batches are accepted only for 2025-03-26, the one version that had them.
- **Modern**, 2026-07-28: `server/discover` and per-request `_meta`, with no handshake and no session
  state.

1.3.0 speaks 2025-06-18 and older only, and answers a client that asks for anything newer with
2025-06-18.

## Security

- **Only `ask` and `run` spend money,** and they call only the providers in your config (or the
  default engines) with your keys. Keep your client's confirmation on for them. Tool annotations are
  hints, and clients use them differently. For a server that cannot spend, use `--read-only` or
  `--toolsets score` (from 1.4.0).
- **An agent can only lower spending.** `max_calls` and `budget_usd` can lower the caps in the
  config, never raise them, and run ids are validated before any file is read.
- **`score_site` connects only to public addresses.** The scored URL, each redirect hop and every
  URL the site points to must resolve to a globally routable address. A direct connection goes to the
  address that was checked. Through an HTTP proxy, the proxy resolves names, and that last step is
  the proxy's. Use the CLI for intranet sites.
- **Text from the audited site is data.** Evidence quotes it inside `«site text: …»`, and the server's
  instructions tell the agent to report that text, not act on it.
- **Keys** come from the server's environment only, are never written to the config, run files or
  reports, and are redacted from provider error messages. A key in a client config's `env` block is
  stored there in plain text.
- **Files.** Only `run` writes, under `.geo-score/watch/runs/` next to the config.
- **User agents.** `score_site` fetches with a browser user agent and with named AI-crawler user
  agents, to see what those crawlers are served. Provider calls send `geo-score-watch/<version>`.
- **No telemetry.** Nothing is sent to us or anyone else.

The full threat model: [SECURITY.md](../.github/SECURITY.md).

## Troubleshooting

**Look at the server directly.** [MCP Inspector](https://github.com/modelcontextprotocol/inspector)
(Node) talks to it without a client. From a clone, everything before `--` is the server command:

```bash
npx --yes @modelcontextprotocol/inspector@2.8.0 --cli python3 cli/geo_score.py mcp -- --method tools/list
npx --yes @modelcontextprotocol/inspector@2.8.0 --cli python3 cli/geo_score.py mcp -- --method resources/read --uri geo-score://rubric/v1.1
npx --yes @modelcontextprotocol/inspector@2.8.0 --cli python3 cli/geo_score.py mcp -- --method tools/call --tool-name score_site --tool-arg url=example.com
npx --yes @modelcontextprotocol/inspector@2.8.0 --cli python3 cli/geo_score.py mcp -c /absolute/path/geo-score-watch.json -- --method tools/call --tool-name run --tool-arg dry_run=true
npx --yes @modelcontextprotocol/inspector@2.8.0 --cli python3 cli/geo_score.py mcp -- --method prompts/list    # from 1.4.0
```

Without Node, send the handshake by hand:

```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"probe","version":"0"}}}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' | python3 cli/geo_score.py mcp
```

**The server does not start.** A desktop app often cannot find `uvx`: put its absolute path (`which
uvx`) in `command`. The first start downloads the package from PyPI (and a Python, when uv finds none),
which on a slow network can outlast a client's startup timeout; start it once more, or raise the
timeout (Codex: `startup_timeout_sec`). Where PyPI cannot be reached, use the release wheel line under
[Install](#install) instead.

**`cannot read … geo-score-watch.json`.** The server is not running in your project. Pass
`-c /absolute/path/geo-score-watch.json` or set `GEO_SCORE_WATCH_CONFIG`. From 1.4.0, `status` shows
the path the server tried.

**`no engine can run — the MCP server's environment has no API keys`.** The keys did not reach the
server. Desktop apps do not see variables exported in a shell, and Gemini CLI removes them unless they
are listed in `env`. See [Keys](#config-and-keys).

**`score_site` hangs or times out behind a proxy.** Some clients, the MCP Inspector among them, start
the server with only a few variables (`PATH`, `HOME` and the like), so the `HTTPS_PROXY` you exported
never reaches it. Put the proxy in the server's `env` block, or with the Inspector pass
`-e HTTPS_PROXY=http://host:port` after the `--`.

**A `run` is cut off.** The client stopped waiting: raise its tool timeout, or ask fewer with
`limit` and `engines`. See [Timeouts](#timeouts-and-cancelling).

**`cannot resolve <host>`.** The name does not resolve on the machine that runs the server. Check the
spelling, or that machine's DNS and proxy settings. `score_site` resolves every host itself to check that
it is public, even when a proxy fetches the page, so behind a proxy the machine still needs working DNS;
the message says so when a proxy applies. Before 1.5.0 such a host was reported as private.

**`url must be on a public host: <host> resolves to a private, loopback or reserved address`.** The name
resolves, but to an address `score_site` refuses on purpose. Score such a site with the CLI.

**`url must be an http(s) URL on a public host`.** `score_site` refuses localhost, private and
reserved addresses on purpose. Score those sites with the CLI.

**A tool is missing.** `--read-only`, `--toolsets`, `--tools` or `--exclude-tools` (from 1.4.0) left
it out. `score_site` also disappears when the server cannot load `geo_score.py` from the same release
next to `geo_watch.py`. Zed shows tools and prompts, never resources.

**Logs.** The server writes diagnostics to stderr, never to stdout. Claude Desktop keeps them in
`~/Library/Logs/Claude/mcp-server-geo-score.log` on macOS; most other clients show them in an MCP log
or output panel.

More about the scores themselves: [troubleshooting.md](troubleshooting.md).
